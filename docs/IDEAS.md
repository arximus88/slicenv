# Ідеї на майбутнє

Записані побажання користувача. Не реалізовано; перед роботою — окреме обговорення.

## Порівняння рушіїв

Нарізати ту саму модель з тими самими налаштуваннями різними рушіями й версіями
(наприклад OrcaSlicer 2.3 / 2.4 / 2.5, Bambu Studio) і показати різницю поруч:

- час друку й витрата філаменту (мм, г) — з підсумку G-code кожного рушія;
- траєкторії: два попередні перегляди пошарово синхронно або накладання;
- що змінилося в налаштуваннях: значення, які рушій підставив по-іншому
  (різні дефолти профілів між версіями);
- далі — порівняння самих друків: фото/нотатки користувача, прив’язані до
  кожного варіанта.

Що вже є для цього: менеджер рушіїв (кілька версій поруч), `slicer::cli` з
окремим каталогом профілів на версію, `gcode_stats` у MCP.

## Майстер першого запуску й вибір принтера — як в OrcaSlicer

Зразок — Setup Wizard OrcaSlicer 2.5 (скриншоти користувача, 2026-11-09).

**Майстер першого запуску, кроки:**
1. **Вибір принтера.** Сітка карток з фото, групи за вендорами («Custom Printer»:
   Klipper, Marlin, RRF…; далі Bambu Lab, Afinia…). Лічильник «0 / 6» і чекбокс
   на групу, пошук, перемикач вигляду (список / дрібна / велика сітка).
2. **Вибір філаменту.** Три фільтри-колонки (принтер, тип філаменту, вендор)
   з «All» і пошуком; під ними список профілів з чекбоксами, «23 / 436»,
   «Select visible: All / Clear all».
3. **Stealth Mode.** Вимкнути всі хмарні функції для повністю офлайн-роботи.
4. **Пропрієтарні плагіни.** Чекбокс «Install Bambu Network plug-in»
   з поясненням, що плагін не наш і ставиться на ризик користувача; після
   «Finish» — вікно завантаження з прогресом.

**Головна думка:** у звичайних списках потім видно лише вибране в майстрі,
а не всі сотні системних профілів «яких тобі ніколи не треба».

**Блок «Принтер» на Prepare (Orca):** у рядку три контроли, і це зручніше,
ніж у нас:
- **принтер:** іконка + назва. У списку лише вибрані принтери, плюс
  «Select/Remove printers (system presets)», що знову відкриває вибір з
  майстра, і «Create printer»;
- **Variant:** діаметр сопла (0.2 / 0.4 / 0.6 / 0.8) окремим компактним
  випадним списком;
- **стіл:** мініатюра текстури, у списку типи столу (Smooth Cool, Engineering,
  Smooth High Temp, Textured PEI, Textured Cool, Cool Plate (SuperTack)).

## Що перебрати з Mica Slicer

Огляд [steenfeldt/mica-slicer](https://github.com/steenfeldt/mica-slicer) v0.0.5, 2026-11-09.

**Про проєкт.** Слайсер на Rust з власним рушієм: переклад PrusaSlicer 2.9.6 і OrcaSlicer 2.4.2. GUI на egui + wgpu. Alpha, один автор, код переважно згенерований агентом.

**Ліцензія.** Mica під AGPL-3.0-only. Якщо брати його код дослівно, увесь Slicenv фактично стане «only» замість нашого «or later». Тому беремо ідеї, а алгоритми, які Mica сам переклав з PrusaSlicer чи Orca, перекладаємо напряму з upstream (там «or later»). Mica тоді служить мапою: які файли й функції брати.

Повний звіт був у `/tmp/mica-research/REPORT.md`. Нижче — пріоритети.

**Безпека й якість, без чужого коду:**
1. **Ліміти при читанні 3MF проти zip-бомб.** У нас `crates/project/src/threemf.rs` (`load_3mf`) читає кожен запис архіву через `read_to_end` без меж. У Mica є ліміти: архів 2 GiB, 65 536 записів, текст 256 MiB, читання через `Read::take`.
2. **Фазинг парсера 3MF** (cargo-fuzz, щотижневий CI).

**Принтер:**

3. **AMS-мапінг.** Пропонувати слот за типом матеріалу і найближчим кольором (CIEDE2000), з попередженнями й ручною зміною. Зараз ми завжди шлемо `use_ams=false`, `ams_mapping=[-1,…]` (`device.rs`). Перевіряти лише з людиною біля принтера.
4. **Синхронізація котушок AMS → філаменти проєкту**, попередження про розбіжність.
5. **Preflight перед відправкою.** Лише поради: принтер зайнятий, не той матеріал, тип столу.
6. **Камери X1/P2S/H2D: RTSPS + системний декодер H.264** (VideoToolbox / Media Foundation / GStreamer). Для Klipper — WebRTC.

**Нарізка й Prepare:**

7. **Кеш нарізок за хешем входів.** Після undo результат миттєвий. Для нас це особливо цінно, бо рушій зовнішній і повільний.
8. **Guard rails пресетів** з виправленням в один клік: шар не пасує до сопла, 0 стінок, 0 верхніх шарів, температура поза межами філаменту…
9. **Панорамування за схопленою точкою.** Зараз `viewer/src/camera.rs` (`pan`) зсуває камеру на глибині цілі, і на великому наближенні точка «втікає» з-під курсора.
10. **Підсумок проєкту по всіх пластинах:** філаменти, час, ненарізані пластини, «Копіювати».
11. **Розкладання NFP** замість пакування рамок рядками. Перекладати з PrusaSlicer arrange2.
12. **Повна авто-орієнтація** (Tweaker-3) з Orca `Orient.cpp`.
13. **Фарбування поверхні: колір, підтримки, шов** (TriangleSelector з PrusaSlicer). Сегментацію робить рушій, нам потрібні лише пензлі, маска й запис у 3MF.

**Preview, MCP, тести:**

14. **Вибір руху під курсором** (ID-буфер). Нові схеми кольорів: прискорення, фактична швидкість, час шару.
15. **MCP `render_view` / `pick`**: CPU-рендер для агента, без GPU.
16. **Monkey-тест GUI** з інваріантами: undo/redo повертає ту саму сцену, жодних панік і зависань.

**Не брати:**
- рушій нарізки Mica;
- код UI на egui;
- його розв’язувач профілів;
- PrusaLink і Prusa Connect;
- самооновлювач;
- Docker / Selkies.
