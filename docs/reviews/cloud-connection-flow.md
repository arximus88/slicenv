# Аудит: підключення принтерів (майстер, Bambu Cloud, відкритий плагін, «Пристрій»)

Стан на 2026-11-10. База — `main` `2c578f1`; окремо оцінено `dfbb871` з гілки
`fix/cloud-login-activation` (ще не в main). Код не змінювався.

Номери рядків — за `main` `2c578f1`. Де йдеться про `dfbb871`, це позначено явно.

## Висновок

1. Інцидент користувача — це один дефект моделі, а не тексту: майстер вважає «Готово» наявність
   файлу сесії, а робочий потік хмари окремо відмовляється з’єднуватися, бо `block_cloud = 1`.
   Ці два стани ніде не зводяться докупи.
2. `dfbb871` закриває саме цей випадок (свіжий вхід з методом Cloud вмикає хмару), але в
   нинішньому вигляді **зливати не варто**: він вмикає хмару ще й при звичайній перевірці
   збереженої сесії, тому перемикач «Друк і стан через хмару» неможливо вимкнути з відкритого
   майстра, і кожне відкриття вкладки Cloud рве робоче з’єднання. Виправлення — два рядки
   (розділ «Порядок виправлень», крок 1).
3. П’ять однакових статусів і вічний спінер — наслідок того, що глобальна фаза хмари
   підставляється замість стану принтера, коли принтер не вибрано. Лікується в одному місці
   (`CloudState::summary`), без нового банера.
4. Інтерфейс росте, бо кожен транспорт і кожна підказка мають власний постійний блок. Нижче —
   модель з одним списком, одним входом «Додати принтер» і підказками лише за потреби.

## Причина інциденту

Ланцюжок на `main` (**К**, наслідок — **З**):

1. Користувач вибрав відкритий плагін. Типове значення — `cloud = false`, `block_cloud = 1`
   (`crates/cloud/src/obn.rs:189-199`).
2. Майстер → Cloud → вхід через браузер. `finish_login` запускає `--cloud-login`, плагін пише
   `obn.auth.json` (`wizard.rs:1352-1365`, `1143-1165`).
3. Колбек ставить `CloudStage::Ready`, `changed = true` і шле `Reconnect`
   (`wizard.rs:991-995`). Перемикач хмари ніхто не чіпає.
4. Робочий потік починає сесію і одразу виходить: `obn::active() && !obn::cloud_enabled()` →
   фраза «Відкритий плагін: хмару вимкнено…» (`device.rs:518-523`).
5. Майстер тим часом показує зелене «Вхід у Bambu Cloud: <нік>» (`wizard.rs:2993-3000`), а крок
   «Готово» — «Bambu Cloud · <нік>» з галочкою (`wizard.rs:3077-3079`).
6. Список порожній, нічого не вибрано, тож `summary()` віддає глобальну фазу
   (`device.rs:309-315`) у п’ять місць:
   - заголовок вікна — `workspace.rs:1270`;
   - тулбар сторінки — `device/pages.rs:37-55`;
   - порожній рядок лівого доку, зі спінером — `device.rs:1784-1791`;
   - рядок «Bambu Cloud: …» під порожнім станом — `device/pages.rs:146-182`;
   - рядок стану — `workspace.rs:1558`.

Патч `b51bbd4` (у main) додав пояснення в діалог друку й кнопку входу в модалку плагіна, але
кнопка видна лише при вже ввімкненій хмарі (`open_plugin.rs:274-279`), тож із цього стану вона
не виводить.

## Оцінка `dfbb871`

Що робить: нова `wizard_cloud_ready` (`dfbb871` `wizard.rs:850-867`) викликається після входу
паролем (`:960`), входу через браузер (`:1008`) **і після перевірки збереженої сесії**
(`wizard_own_nickname`, `:877`). Якщо метод — Cloud, OBN активний і хмара вимкнена, викликає
`obn::set_cloud(true)`, далі `Ready`, `changed = true`, `Reconnect`.

Що виправляє (**К**): сценарій користувача. Після `set_cloud(true)` міняється і файл вибору, і
`obn.conf`; робочий потік отримує `Reconnect` (а `setup_stamp` ще й сам помітить зміну за 2 с,
`device.rs:441`, `489-495`). Застряглий стан користувача (сесія є, `cloud = false`) теж
лікується: досить відкрити вкладку Cloud у майстрі.

Що ламає:

| # | Severity | Суть |
|---|---|---|
| P1 | **High** | Перемикач хмари не вимикається з відкритого майстра. `obn_toggle_cloud` → `obn_changed` → `wizard_check_cloud`, бо `self.wizard.is_some()` (`open_plugin.rs:108-110`) → сесія власна → `Ready` → `wizard_own_nickname` → `wizard_cloud_ready` → `set_cloud(true)`. Тост каже «Хмару вимкнено», за кілька секунд вона знову ввімкнена. Модалку з майстра відкриває кнопка «Налаштувати…» на вкладці Cloud (`wizard.rs:3025-3028`), тобто метод саме Cloud. **К** |
| P2 | Medium | Хмара вмикається без дії користувача: досить відкрити вкладку Cloud зі збереженою сесією. Це суперечить коментарю в самому патчі («A saved OBN session alone does not change its default LAN-only setting») і `docs/OPEN-PLUGIN.md` («`block_cloud = 1` типово», хмара — за перемикачем). Наслідок не косметичний: з `block_cloud = 0` плагін тримає хмарний MQTT і вивантажує моделі в хмару Bambu. **К** |
| P3 | Medium | Кожна перевірка сесії тепер шле `Reconnect` і ставить `changed = true`, навіть коли нічого не змінилося. `Ready` після патча все одно означає «сесію записано», а не «принтери видно» (дефект D1 нижче).

## UX-модель: один список, один вхід, стан в одному місці

Принцип: постійний інтерфейс не залежить від кількості транспортів, моделей і прошивок. Усе, що
стосується конкретного принтера чи конкретної відмови, з’являється лише біля нього й лише тоді.

### 1. Один стан з’єднання на джерело

Замість рядка-фази — значення з п’яти станів для кожного джерела (Bambu Cloud, LAN, Klipper):

`Вимкнено` · `Потрібна дія (що саме + одна кнопка)` · `Підключення` · `Працює (N принтерів)` ·
`Помилка (текст + «Повторити»)`

- Його обчислює робочий потік; майстер і діалог друку **читають** його, а не виводять власний
  з файлів. `CloudStage::Ready` зникає як окреме джерело правди: стан кроку =
  «плагін ✓ → акаунт ✓ → з’єднання: <живий стан потоку>».
- «Хмару вимкнено у відкритому плагіні» стає `Потрібна дія` з кнопкою «Увімкнути хмару», а не
  фразою без дії.

### 2. Глобальний статус показує принтер, а не хмару

- Заголовок вікна, тулбар сторінки, рядок стану: стан **вибраного принтера**. Принтера немає —
  нейтральне «Немає принтера», без фази хмари.
- Стан джерел показується рівно в одному місці: рядок унизу лівого доку
  (`Bambu Cloud · працює · 3` / `Bambu Cloud · потрібен вхід [Увійти]`). Його ж читає порожній
  стан у центрі — без власного дубля.
- Спінер — лише для стану `Підключення`.

Це прибирає чотири з п’яти повторів і не додає жодного елемента.

### 3. Лівий док: один список

```
Принтери                         [+]  [⟳]
  ● A1 «BORO»      LAN · друкує 42%
  ● P2S «3dsyrun»  Хмара · вільний
  ○ X1C            Хмара · офлайн
  ─ Знайдено в мережі (2)           ▸     ← згорнуто, якщо є хоч один доданий
────────────────────────────────────────
Bambu Cloud · працює                      ← один рядок джерел, клік — деталі
```

- Блоки «Локальна мережа», «Klipper», «Додати за серійним номером» зникають як постійні.
  Їхні дії переїздять у `[+]`.
- Знайдені, але не додані принтери — згорнута група в тому самому списку, що прокручується
  разом з ним. Десять принтерів чи десять знайдених нічого не стискають.
- Транспорт — мітка в рядку (вона вже є: `device.rs:1687-1693`).

### 4. Один діалог «Додати принтер»

`[+]`, порожній стан і крок майстра відкривають той самий компонент:

```
Додати принтер        ( Bambu в мережі | Bambu Cloud | Klipper )
────────────────────────────────────────────────────────────────
<один список або одна форма вибраного способу>
```

- Три великі картки з описами → один рядок-перемикач і одне речення під ним для вибраного
  способу. «Пізніше» — це кнопка «Пропустити» в підвалі майстра, а не третя картка.
- **Bambu в мережі**: список з обмеженою висотою і прокруткою; останній рядок — «Інший (IP і
  серійник)…». Поле коду з’являється для вибраного рядка. «Де взяти код?» — розкривна підказка
  з текстом **для моделі вибраного принтера** (модель відома з оголошення в мережі), а не
  постійний макет з переліком усіх моделей.
- Нотатка про прошивки показується лише коли це стосується дії: принтер відповів відмовою
  керування (`LanError::ControlLocked` уже є) або користувач натиснув «Друкувати». На кожну
  прошивку — рядок у таблиці текстів за кодом відмови, а не новий блок.
- **Bambu Cloud**: три рядки-кроки зі станом — плагін, акаунт, з’єднання. Розгорнутий лише той,
  що потребує дії. Після входу — «<нік> · 3 принтери» і «Вийти». Відкритий плагін — рядок
  «Плагін: закритий Bambu / відкритий (сторонній) [Змінити…]», а не окрема картка під формою.
- Вхід у хмару з діалогу друку відкриває цей діалог на вкладці Cloud, а не майстер першого
  запуску (D15).

### 5. Перемикач хмари відкритого плагіна — одне джерело правди

- Хмару вмикає **дія користувача**: перемикач у модалці або свіжий вхід з вкладки Cloud. Перевірка
  збереженої сесії нічого не вмикає.
- Після автоматичного ввімкнення — видимий рядок у кроці «з’єднання»: «Хмару для відкритого
  плагіна ввімкнено: моделі вивантажуються в Bambu Cloud [Вимкнути]».
- Якщо сесія є, а хмара вимкнена, крок «з’єднання» показує `Потрібна дія` з кнопкою
  «Увімкнути хмару».

### 6. Діалог друку

Нотатка про відкритий плагін показується лише коли чогось бракує, одним рядком з однією дією
(«Хмара вимкнена [Увімкнути]» або «Потрібен вхід [Увійти]»). Коли все готово — нічого.

## Порядок виправлень

Кроки 1–3 — малі й незалежні, без зміни розмітки. Кожен наступний спирається на попередні.

1. **Довести `dfbb871` до зливання** (P1–P3). `wizard_own_nickname` повертає до старої
   поведінки (лише записати нік), а `wizard_cloud_ready` лишається тільки для свіжого входу
   (пароль, браузер). Для сесії, що вже є при вимкненій хмарі, — кнопка «Увімкнути хмару» у
   стані `Ready` замість мовчазного ввімкнення. `Reconnect` і `changed` — лише коли щось
   справді змінилося.
2. **Чесний стан робочого потоку** (D2, D3, D4, D5). На виході з `session()` слати
   `Link(false)`; у режимі очікування на `CloudCmd::Print` відповідати
   `PrintSent(Err(…))`; перевіряти `is_server_connected` перед фазою «Підключено»; очищати
   `cloud.error` і хмарний список на початку нової сесії; кеш `printers.json` прив’язати до
   акаунта або не читати після зміни сесії.
3. **Вхід через браузер без майстра** (D8, P4). `finish_wizard` скасовує очікування браузера.
   Колбек входу не залежить від `this.wizard`: `Reconnect` і тост ідуть завжди.
4. **Один статус** (D16, D7). `summary()` без вибраного принтера віддає нейтральний текст;
   фаза хмари — в одному рядку доку; спінер лише під час підключення. Вибір принтера в
   інтерфейсі — як у потоці (перший онлайн, інакше перший).
5. **`Ready` = стан потоку** (D1, D19). Стан Cloud у майстрі й рядок на кроці «Готово» читають
   `ws.cloud`; галочка — лише після з’єднання.
6. **Діалог друку за станом** (D14) і **вихід з акаунта** (D13).
7. **Розмітка, що не росте** (D17, D18). Спершу дешеве: обмежити висоту списків і згорнути
   знайдені; прибрати постійну нотатку про прошивки й макет екрана в розкривну підказку. Потім
   — один список у доку й один діалог «Додати принтер» (модель вище, пункти 3–4).
8. **Дрібне** (D6, D9, D10, D11, D12, D15, D20): кешувати результат `is_open_plugin` за
   `(шлях, розмір, mtime)`; номер покоління для `wizard_check_cloud`; «Надіслати код знову» у
   фоні; сторінка в браузері «Поверніться до Slicenv» замість «Вхід виконано».

Кроки 1–3 варто покрити тестами без GUI: логіка «коли вмикати хмару» і «що відповідає потік у
режимі очікування» виноситься в чисті функції так само, як `print_paths::choose`.

## Обмеження аудиту

- Поведінка плагіна OBN з `block_cloud = 0` (вхід, `connect_server`, список принтерів, хмарний
  друк) наживо не перевірялася ні тут, ні раніше (`docs/OPEN-PLUGIN.md`, «Лише за кодом»). Усі
  твердження «з `dfbb871` принтери з’являться» — **К** до виклику плагіна і **П** далі.
- Чи відновлює OBN вхід (`is_user_login`) при `block_cloud = 1` — **П**. Від цього залежить, чи
  дійде `--cloud-whoami` до успіху в рядках 2 і 4 таблиці; знімок користувача (майстер показав
  вхід виконаним) це підтверджує побічно.
- Розміри в D17 і D18 пораховані з констант розмітки, а не виміряні на десяти принтерах:
  `SLICENV_LAN_OFF=1` не дає знайдених принтерів, а справжню мережу чіпати не можна.

### Не перевірялося

- Справжній Bambu Cloud, плагін (закритий і OBN), вхід через браузер, `connect_server`,
  список принтерів, хмарний і LAN-друк, `Reconnect` на живій сесії — заборонено умовами.
  Усе про робочий потік поза чистими функціями — **К**.

  у тестовому режимі (`SLICENV_CLOUD_OFF`) робочого потоку немає.
