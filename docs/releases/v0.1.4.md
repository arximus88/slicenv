# Slicenv 0.1.4

![Slicenv styles: GNOME Adwaita dark and light, default One Dark, Omarchy Gruvbox](https://github.com/arximus88/slicenv/releases/download/v0.1.4/slicenv-0.1.4-styles.png)

## What's new
- **At home on GNOME.** On GNOME the app now uses the neutral Adwaita palette (dark and light) with your system accent colour, a header bar with rounded tabs and round window buttons placed according to your GNOME settings, pill-shaped floating toolbars and a filled primary button. Page layout and density are unchanged. On Omarchy the app keeps following the Omarchy theme; elsewhere it keeps the One Dark / One Light look. `SLICENV_SKIN=gnome|zed` switches by hand.
- **Engine installation stays visible.** After you close the wizard or the packages window, the status bar shows the step and percentage on every page; clicking it opens the packages window, which now has a **Cancel** button.
- **The new engine switches on by itself** when there was none, with a notification when it is ready. Cancelling is no longer shown as an error.
- Flatpak manifest: the pinned commits of squashfs-tools, Clipper2 and manifold are restored (they were overwritten since 0.1.2).

### First launch on macOS
The build is not signed with an Apple Developer ID and is not notarized, so macOS blocks it. Open it once, press Done, then go to **System Settings → Privacy & Security** and press **Open Anyway** next to Slicenv. Or run `xattr -dr com.apple.quarantine /Applications/Slicenv.app`. The same steps are in "Read Me First.txt" inside the disk image.

On Windows, SmartScreen warns about an unknown publisher: **More info → Run anyway**.

## Known limits
- In the GNOME look, clicking the window buttons, dragging by the header bar and double-click were not tested with a real mouse; changes to the GNOME button layout need an app restart in this version.
- The macOS and Windows builds were built in CI only and not run on real machines.
- The Linux packages of this release were built in an Ubuntu 22.04 container with the same steps as CI (GitHub's runners could not install system packages that day); they require glibc 2.35 or newer, as before.
- Slicing runs only in the active tab; closing the window does not ask about unsaved changes in tabs.
