# Slicenv 0.1.3

## Зміни

- Профілі OrcaSlicer 2.5 читаються з кешу `.opc` у самому пакеті рушія: без мережі й одразу. Раніше після встановлення 2.5.0 «Завантаження профілів · 0 / 2496» могло висіти вічно.
- Завантаження профілів з GitHub (запасний шлях) не зависає в мережах, де IPv6 до raw.githubusercontent.com не завершує TLS; лічильник рухається по одному файлу.
- Без рушія кнопка «Нарізати» стає «Встановити рушій» і відкриває встановлення; картка Preview і панель профілів кажуть те саме.
- «Друкувати» працює й без під’єднаного принтера: нарізаний файл передається в Bambu Connect або відкривається у встановленому Bambu Studio. Це шлях друку через хмару на macOS.
- Бібліотека моделей більше не обходить усю домашню теку: без вибраної теки вона порожня. На macOS це прибирає запити на доступ до музики, фото й робочого столу.
- Пакети Bambu Studio 02.09 підписані як Ubuntu 22.04 / 24.04; майстер ставить збірку для 24.04.
- В образі для macOS — інструкція першого запуску.

## Перевірка

- Повна перевірка: 600 тестів успішні, 0 падінь; clippy й переклади пройшли.
- Читач кешу звірено зі справжнім `BBL.opc` OrcaSlicer 2.5.0 (2490 профілів); регресія нарізки справжнім рушієм на цих профілях збігається з еталоном.
- Стани «немає рушія» й «немає принтера» пройдено в ізольованому вікні на Linux.

## Відомі межі

- Передача в Bambu Connect і Bambu Studio на macOS не перевірялась на справжньому Mac.
- Збірки для macOS і Windows не підписані; на macOS потрібен дозвіл у «Приватність і безпека».
- Нарізка лише в активній вкладці; закриття вікна не питає про незбережені зміни.
